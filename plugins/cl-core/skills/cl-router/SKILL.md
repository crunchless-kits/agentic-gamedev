# Crunchless router

Pick the narrowest member that fully covers the task. Read `references/routing-table.md` only when the right member is not obvious; it maps tasks to members and run profiles for every installed plugin. Reach a member through its plugin's hub (the Hubs table below) unless it is free and listed.

## Execution model (how to spend tokens)

- Scout first: `cl-scout` (haiku, low, read-only) gathers evidence for audits, traces, gates, and reports.
- Build second: `cl-builder` (sonnet, medium) executes one bounded skill procedure once decisions are made. Builders run in parallel only on disjoint files, assigned up front.
- Analyze on sonnet at high: analysts, diagnostics, QA attack passes, marketing, publishing, and the producer combine facts.
- Decide last on opus at medium: only ship or no-ship, root cause across systems, ranking many findings, architecture, and design decisions. Reviewers do not fix while reviewing; they route fixes to a builder and re-check.
- Model and effort are pinned in frontmatter on every agent, command, and forked skill (`docs/model-routing.md` in the kit repo). Forked skills name `agent: cl-core:cl-builder` (bare `cl-builder` in vendored installs).
- High effort is opt-in: `--deep` on a command, or a user who asks, launches the deciding agent with the Agent tool's `effort: high`. Never ask the user to change session effort.
- Scripts before reasoning: when a skill ships `scripts/`, run them first and reason over their JSON.
- Fan-out has fixed overhead per subagent: at most 3 subagents in parallel unless `maxParallelAgents` or `CL_MAX_PARALLEL` says otherwise, and batch small steps into one scout or builder.
- Hidden members: to keep the skill listing inside its budget, each plugin lists one hub skill, and its other skills carry `disable-model-invocation: true`. Never call the Skill tool on a hidden member, even when a skill, agent, or table names it: Claude Code refuses the call and asks the user to type the command. Invoke the member's hub instead, or Read the member's SKILL.md when you already have its path (vendored installs: `.claude/skills/<name>/SKILL.md`). Users can still type `/<member>` themselves.
- Snapshot age: before portal, ad-network, store, CI, or asset work, check the `Last verified` line in the skill's `references/` notes (or run `node scripts/verify_refs.mjs` in the kit repo). Older than 90 days means re-verify first and say so.

## Run profile (every skill)

A skill that says `Run profile: router.` runs this way; a `Fan-out:` line adds only that skill's partitions and order.

- Facts, inventories, checklists, snapshot checks, and bundled scripts: one `cl-scout`, or one scout per named group.
- Implementation on known files: `cl-builder`, one per disjoint file set.
- Judgment (design, ranking, verdicts, causes): the caller, at the model and effort its frontmatter pins.
- A forked skill gets no conversation history, so the argument carries the file paths and decisions.

## Primitives (shipped as dependencies)

Each engine harness ships its primitives as dependencies pulled from upstream, never copied into the kit. These include official CLIs, MCP servers, libraries, and community skill packs. Each engine's list is in its `primitives.json`, and `<engine>-setup` installs and pins them. Route primitive questions to the installed primitive or to the engine's own docs for the installed version, and keep this kit's rules on top: read before write, verify versions, measure, and finish with a handoff. The `*-feature-playbook` skills show how the two fit together.

## Shared rules

0. Read the project profile (`docs/crunchless.profile.json`), the house rules (`docs/house-rules.md`), and the learned house files (`.cl/house/INDEX.md`, written by `/cl-learn`) first when they exist; they hold the engine, audience, reference devices, test gate, operating context, quality floor path, output paths, and writing rules. Missing fields are asked one question at a time, only when the answer is the user's to give; otherwise state the assumption and move on.
1. Read before write. Quote file paths as evidence. A fix without a located cause is a guess.
2. Never guess an SDK, portal, store, or provider API. Read the skill's reference snapshot, then the live official docs; stop at the boundary with `TODO(verify)` when verification is impossible.
3. Business code (portal SDKs, ads, purchases, analytics, remote config, saves, backends) stays behind game-owned interfaces, one adapter per provider.
4. Measure before and after any performance or feel change. Before calling a web game ready for a portal or for release, run `web-portal-preflight` when it is installed, fix what fails, and report its result. A game that was never run is unverified.
5. Protect the player and the build: no destructive git, no deleted assets, no live dashboard changes or rollouts without the user saying so.
6. Keep outputs tight: ranked top ten for findings, lists capped at five, handoff at most eight lines.
7. Evidence over description: a gate passes on a recording, a screenshot, a measured number, or a file, never on a statement of what should be true; label findings Measured, Seen, Code, or judgment, and figures [seen], [sourced], [starting value], or estimated. Report readings as measured; never adjust a number to look better.
8. Zero-context checking for anything a stranger will read: a fresh reader with no project context, no tools, and a fixed brief (`cold-read`).
9. Fix the source, then rerun the project's own checks; one home per document, with one-way mirrors that say "do not edit".
10. No slop: anything people read or look at passes `slop-check` before it ships; tells stay only when the style guide names them as deliberate.
11. Durable work goes in a file with a role line (instructs, records, reference, hands off) and a changelog; draft, show, and stop before writing into anything shared; rulings belong to the user and are recorded only when stated.

## Handoff format

Every member finishes with this block, at most eight lines; a member names only the fields it fills differently. `Ran as` is for subagents and forks.

```
## Handoff
Changed: <files, or nothing>
Ran as: <model and effort; unverified if the tool does not show it>
Evidence: <what was read or measured, paths or numbers>
Verify: <exact steps or commands>
Open: <unverified, deferred, or needs a decision>
Next: <single most useful action>
```
