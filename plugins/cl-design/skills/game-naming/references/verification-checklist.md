# Verification checklist (run by the user; the skill only produces Level 1 filters)

Registries change constantly and the skill cannot query them live. Treat the shortlist as a starting point and clear each finalist in this order. Stop at the first hard conflict.

1. Web search: the exact name plus "game", "studio", "app", "tool", and the field. A shipping product with the same name in games or developer tools is a hard conflict; a dormant product is a soft one.
2. Domains: a bulk domain checker at a registrar. If the exact `.com` is parked or priced for resale, pick the modifier or ending strategy from the shortlist rather than paying.
3. Trademarks: search the trademark database for each market you will sell in (for example the United States, the European Union, the Philippines, or wherever the company is registered), for the exact name and close phonetic spellings, in the classes that cover software and games (commonly class 9 for software, class 41 for games and entertainment services, class 42 for software services). A live registration in those classes by an unrelated company is a hard conflict; consult a trademark attorney before filing.
4. Social handles: a handle checker across the networks the audience uses (and GitHub or itch.io for a developer brand). Consistent handles with a short suffix are acceptable.
5. Package registries when the name is also a tool: npm, PyPI, crates, and Claude Code marketplaces, so install commands do not collide.
6. Languages: ask native speakers of the audience's main languages whether the name sounds like anything unfortunate.
7. Decide, then register the domain and handles the same day; shortlists leak.

Record the result next to the shortlist: name, date, each check, conflicts found, decision.
